# Configulator

[![go.mod version](https://img.shields.io/github/go-mod/go-version/USA-RedDragon/configulator.svg?filename=v2/go.mod)](https://github.com/USA-RedDragon/configulator) [![coverage](https://raw.githubusercontent.com/USA-RedDragon/configulator/main/.github/badges/coverage-v2.svg)](https://github.com/USA-RedDragon/configulator/actions/workflows/v2.yaml) [![License](https://badgen.net/github/license/USA-RedDragon/configulator)](https://github.com/USA-RedDragon/configulator/blob/main/LICENSE)

Load a Go config struct from defaults, a config file, environment variables
and command-line flags, using code generated by `go generate`.

There is also a Rust version,
[configulator-rs](https://github.com/USA-RedDragon/configulator-rs). Both
follow the [spec](spec/SPEC.md).

## Installation

Requires Go 1.27 or later.

```sh
go get github.com/USA-RedDragon/configulator/v2
go get -tool github.com/USA-RedDragon/configulator/v2/cmd/configulator
```

## Getting started

```go
package main

//go:generate go tool configulator -type Config

import (
	"fmt"
	"log"

	"github.com/goccy/go-yaml"
	"github.com/spf13/pflag"

	configulator "github.com/USA-RedDragon/configulator/v2"
	cpflag "github.com/USA-RedDragon/configulator/v2/flags/pflag"
)

type Config struct {
	LogLevel string `name:"log-level" default:"info" description:"log level"`
	HTTP     HTTP   `name:"http"`
}

type HTTP struct {
	Host string `name:"host" default:"localhost" description:"listen address"`
	Port uint16 `name:"port" default:"8080" description:"listen port"`
}

func (c Config) Validate() error { return nil }

func main() {
	c := configulator.New(ConfigSchema()).
		WithEnvironmentVariables(&configulator.EnvironmentVariableOptions{Prefix: "MYAPP_", Separator: "_"}).
		WithFile(&configulator.FileOptions{
			Search:   []string{"config.yaml"},
			Decoders: configulator.Decoders{".yaml": yaml.Unmarshal},
		})
	cpflag.Bind(c, pflag.CommandLine, ConfigPFlagHooks(), nil)
	pflag.Parse()

	cfg, err := c.Load()
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(cfg.HTTP.Host, cfg.HTTP.Port)
}
```

Run `go generate ./...` to write `config_configulator.go`. Now `http.port`
can be set with `http: {port: 9000}` in `config.yaml`, `MYAPP_HTTP_PORT=9000`,
or `--http.port=9000`, and `--config` picks a different file.

More in [v2/examples](v2/examples): [all](v2/examples/all) (YAML, cobra,
origin report), [minimal](v2/examples/minimal), [jsonv2](v2/examples/jsonv2)
(no flags), [toml](v2/examples/toml) and [stdflag](v2/examples/stdflag).

## Features

- Configuration from, lowest to highest priority:
  - Defaults in struct tags
  - Files: JSON is built in (`encoding/json/v2`); YAML, TOML or anything
    else works by registering a decoder for its file extension
  - Environment variables
  - Command-line flags, using `spf13/pflag` or the standard library `flag`
    (or no flag library at all, with `-flags=none`)
- No reflection at runtime: `go generate` writes the loading code
- Supported types:
  - Every scalar except complex numbers
  - Nested structs, and pointers to scalars or structs for optional values
  - Slices of scalars
  - Maps and slices of structs (files only)
  - These standard library types:
    - `time.Duration` (`30s`)
    - `time.Month` (`March` or `3`)
    - `*time.Location` (`America/New_York`)
    - `net.IPNet` (`10.0.0.0/8`)
    - `net.TCPAddr` and `net.UDPAddr` (`host:port`)
    - `net.HardwareAddr` (`aa:bb:cc:dd:ee:ff`)
    - `url.URL`
    - `os.FileMode` (`0644`)
- `Report()` lists where each field's value came from: its default, the
  config file, an environment variable or a flag, naming which one
- Fields tagged `secret:"true"` are redacted in `PrintConfig()` output and in
  error messages
- Fields tagged `required:"true"` make `Load()` fail if nothing sets them
- The generator can also print a JSON Schema, a sample config file (YAML,
  JSON or TOML), or a Markdown table of every option

## Struct tags

| Tag | Meaning |
| --- | --- |
| `name:"key"` | Key in files, env and flags. Falls back to the `json` or `yaml` tag |
| `default:"value"` | Default value, checked when generating |
| `description:"text"` | Flag help text, and the description in generated docs |
| `env:"NAME"` | Use `NAME` for this field's part of the env var name. `env:"-"` skips env |
| `flag:"name"` | Use `name` for this field's part of the flag name. `flag:"-"` skips flags |
| `short:"p"` | Flag shorthand (pflag only) |
| `secret:"true"` | Redact in `PrintConfig()` and error messages |
| `required:"true"` | `Load()` fails if nothing sets it |
| `opaque:"true"` | Decode the type with its `UnmarshalText` method |

Env var names are the prefix plus each level's name, uppercased, with `-`
turned into `_`: `http.listen-port` is `MYAPP_HTTP_LISTEN_PORT`.

## Generator flags

| Flag | Meaning |
| --- | --- |
| `-type` | Config type (required) |
| `-dir` | Package directory, default `.` |
| `-output` | Output file, default `<type>_configulator.go` (lowercased) |
| `-flags` | `pflag` (default), `std` or `none` |
| `-no-validate` | Don't require a `Validate() error` method |
| `-schema` | Print a JSON Schema instead of generating code |
| `-sample` | Print a sample config instead of generating code. `-format` picks `yaml` (default), `json` or `toml` |
| `-markdown` | Print a Markdown table of every option instead of generating code. `-env-prefix`, `-env-separator` and `-flag-separator` set how names are shown |
| `-markdown-file` | With `-markdown`, write the table into a file between the configulator markers |
| `-sample-file` | With `-sample`, write the sample to a file, such as `config.example.yaml` |
| `-check` | With `-markdown-file` or `-sample-file`, exit 1 if the file is out of date instead of writing it |

## Config docs and example config

`-sample -sample-file config.example.yaml` writes a commented example config.
For the README, put the markers where the table should go:

```markdown
## Configuration

<!-- configulator:begin -->
<!-- configulator:end -->
```

Then fill it in from `go generate`, pre-commit, or CI:

```go
//go:generate go tool configulator -type Config -markdown -markdown-file ../../README.md -env-prefix MYAPP_
//go:generate go tool configulator -type Config -sample -sample-file ../../config.example.yaml
```

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/USA-RedDragon/configulator
    rev: v2.2.0
    hooks:
      - id: configulator-generate
        args: [-dir, internal/config, -type, Config]
      - id: configulator-markdown
        args: [-dir, internal/config, -type, Config, -markdown-file, README.md, -env-prefix, MYAPP_]
      - id: configulator-sample
        args: [-dir, internal/config, -type, Config, -sample-file, config.example.yaml]
```

```yaml
# GitHub Actions: fails pull requests with a stale README or example config,
# and commits the update on pushes to the default branch.
- uses: USA-RedDragon/reusable-actions/configulator-docs@v2
  with:
    dir: internal/config
    type: Config
    env-prefix: MYAPP_
```

The hooks and the action run `go tool configulator`, so they use the version
in your `go.mod`.

## v1

v1 is the root module, `github.com/USA-RedDragon/configulator`. It uses
reflection, gets bug fixes only, and new code should use v2.

<details>
<summary>v1 documentation</summary>

### Features

- Supports configuration from:
  - YAML or JSON files
  - Environment variables
  - Command line arguments (`spf13/pflag`)

### Supported types

Working: all scalars except complex, structs, arrays of scalars.

Not working: maps, arrays of maps, arrays of structs, multi-dimensional
arrays, complex scalars.

### Usage

v1 uses the `name`, `default`, and `description` tags. Fields without a
`name` tag are ignored. The name can also come from a `json` or `yaml` tag.

```go
// Field appears in config files, environment variables, and command line arguments as key "myName".
Field int `name:"myName"`

// Field has a description if seen in the CLI's --help
Field int `name:"myName" description:"this text appears in the help section of the CLI"`

// Field has a default value of 1
Field int `name:"myName" default:"1"`
```

Keys are matched case-insensitively across layers (`http.host` in YAML is
`HTTP__HOST` in the environment), so v1 can't tell apart two fields whose
names differ only in case. Nested env var names use the Go field name, not
the tag name.
